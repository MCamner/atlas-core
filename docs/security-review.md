# Security Review: v2.0 Readiness

Review date: 2026-09-26. Scope: the checked-in Core implementation and
`.github/workflows/test.yml`. This is an internal review, not the independent
security review required by the v2.0 exit gate.

## Threats and controls

| Threat | Current controls | Residual risk / required action |
| --- | --- | --- |
| Prompt injection in repository or tool output | Repository content is data; tool capabilities and write approval are enforced in code. Negative cases are in the P0.3 attack tests. | Core cannot guarantee that an external model ignores malicious content. Review model/provider use and retain human review. |
| Supply-chain compromise | Core declares no runtime dependencies. CI requests `contents: read` and runs tests, mypy and pyright. | CI installs unpinned actions and Python tooling; there is no dependency lock, dependency audit, SBOM artifact or automated dependency review. Pin action SHAs and tool versions, generate an SBOM, and gate dependency changes before claiming this control is complete. |
| Secret exposure | Provider keys stay out of run metadata; exported run documents are redacted. Secret-shape tests cover known patterns. | Redaction is deliberately narrow, does not detect arbitrary personal data, and is not a substitute for secret scanning. No repository secret-scanning CI gate is configured. Enable GitHub secret scanning or add a pinned scanner and verify it on pull requests. |
| Path traversal and symlinks | Snapshot containment, path validation and negative tests reject escape paths and symlink reads. | A directory component can still change between resolution and open; see the TOCTOU boundary in `safety-model.md`. |
| SSRF / network access | Core has no generic URL tool; the optional GitHub reader targets the GitHub API. Tool gateway denies network capability by default. | Trusted custom adapters execute with host privileges and can open arbitrary network connections. Do not register unreviewed adapters; isolate them externally. |
| Exfiltration through output | Bounded observations/output and redaction reduce accidental disclosure. | A model may repeat sensitive source content, and redaction is not comprehensive. Inspect artifacts before sharing; do not treat logs as safe merely because they were generated by Core. |
| Privileged writes | `atlas run` is read-only. `atlas propose` binds one write to a human-approved diff and checks it after writing; rollback removes its branch when verification fails. | The test command supplied to `atlas propose` runs as the caller. Process isolation is not an OS sandbox; review the command and run untrusted tests under reduced OS privileges. |

## CI evidence and release blockers

The current required workflow is `.github/workflows/test.yml`: one Ubuntu
runner, Python 3.11, unit tests, mypy and pyright. It has read-only repository
permissions, but action references use mutable version tags and the installed
Python tools are not pinned. No SBOM, secret scan, dependency review or
dependency audit runs in CI. Repository branch protection and GitHub Advanced
Security settings cannot be verified from this checkout.

Do not mark the security P2 item complete until all of the following are
verified on the hosting repository:

- Actions and CI tool dependencies are pinned to reviewed versions; update
  automation is enabled and reviewed.
- A generated SBOM is attached to the release artifact and matches the built
  package.
- Secret scanning runs on pull requests and the default branch, with a tested
  non-secret fixture proving the gate fails on a known test credential.
- Required status checks protect the release branch; the test, type-check,
  dependency and secret-scan gates cannot be bypassed by ordinary changes.
- An independent reviewer examines this threat model, implementation and
  residual risks.

The repository evidence alone cannot establish organization-level branch rules
or an independent review. Those are intentionally not claimed here.
